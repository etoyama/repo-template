# ADR-0022: 無人の実行は、Run now の後に、本番の時刻の1回を無人で通してから完了にする

## Status

Accepted

## Context

PM セッションのスキル `.claude/skills/pm-session/SKILL.md` と [docs/WORKFLOW.md](../WORKFLOW.md) には、
無人で走るもの（デスクトップアプリのスケジュール実行など）を、どこまで確かめたら完了にするかの決まりが無い。

このテンプレートの派生先 etoyama/knowledge-enhance の Epic 1（[#2](https://github.com/etoyama/knowledge-enhance/issues/2)、2026-11-23〜27）で、
次のことが起きた。振り返り（#2 の[コメント](https://github.com/etoyama/knowledge-enhance/issues/2#issuecomment-7215229679)）と、
派生先の ADR-0016 の Context を読んで確かめた。

- 初版の前の検証（v1、2026-11-23）: 無人の実行で vault と db に書いた。1回目は権限の確認で止まった。人間が Run now で許可した後は通った。
  このときの実測は vault への書き込み1件と、db の小さな文書1件だった。
- S7（2026-11-25〜27）で、実物の手順をスケジュール実行に載せた。Run now で許可した後の無人の実行が、3回それぞれ別の形で、権限の確認で止まった。
  1. `$(…)` と `&&` をつないだ複合コマンド。
  2. 毎晩パスが変わる `mkdir` と `node` のコマンド。シェルの許可はコマンドの文字列そのままで残るので、Run now の許可は翌晩の文字列に効かなかった。
  3. `ArtifactData` の `out_dir` を、作業フォルダの外に保存する確認。この確認には「今回のみ許可」しか無かった。
- 派生先ではタスクの権限モードを Auto にし、作業用のフォルダを追加の作業フォルダにして通した（派生先の ADR-0016）。
- Run now では、人間がその場にいて確認に答えられる。本番の時刻の無人の実行では、答える人がいない。止まると、朝の画面のコンテンツが更新されない。

## Problem

- 課題1: Run now で通ったことを完了にすると、無人の実行が止まることに、翌朝まで気づかない。
- 課題2: 止まる形は1回ごとに変わりうる。日付で変わる文字列のように、Run now では出ない確認がある。
- 課題3: 本番の時刻の1回を待つと、完了がスケジュールの間隔だけ延びる。

扱わない範囲: 確認なしで通すための設定（権限モード、許可の一覧）。Epic ごとに違う。

## Decision Analysis

| # | 基準 | 区分 | 分類 | 重み（決めた人） | 出典 |
|---|---|---|---|---|---|
| M1 | 完了にする前に、答える人がいない実行が最後まで通ったことを確かめる | Must | - | - | 課題1 |
| W1 | 本番と同じ条件（日付で変わる文字列、そのときの作業フォルダ）で通る | Want | 解決 | 高（人間。R2 を選んだ） | 課題2 |
| W2 | 完了までの待ち | Want | 費用 | 中（Claude の推測） | 課題3 |

| Must | A. Run now の後に、本番の時刻の1回を無人で通してから完了にする | B. Run now を2回走らせ、2回目に確認が出なければ完了にする | C. Run now の後に、数分後の臨時の1回を置き、無人で通してから完了にする | 何もしない |
|---|---|---|---|---|
| M1 | 満たす | 満たさない（Run now は人間がその場にいる） | 満たす | 満たさない |

| Want | A | C |
|---|---|---|
| W1 | 本番の1回そのものなので、日付で変わる文字列も本番と同じになる | 同じ日の臨時の1回なので、日付で変わる文字列は Run now と同じになり、Epic 1 の2つ目の確認を拾えない |
| W2 | 次の本番の時刻まで待つ（毎晩の実行なら最長1日） | 数分で済む |

- 差がつく基準: W1 と W2。
- 感度: W2 を高にすると C が勝つ。人間が R2 を選んだので W1 を高とした。

| 案 | 起きうる悪い結果 | 抑え方 |
|---|---|---|
| A | 待つ間に、後の Story が無人の実行を前提に進む | 待つ間、ボードの行は `done` にせず、`detail` に次の本番の時刻を書く。後の Story の `depends_on` に入れる |
| A | 止まった1回を直したら、そのまま完了にする | 直したら、次の本番の時刻の1回から数え直す |
| B | Epic 1 と同じく、翌晩に止まる | 抑えられない |
| C | 日付で変わる確認を拾えない | 抑えられない |
| 何もしない | 止まったことに翌朝まで気づかない | なし |

## Decision

A を採る。回し方の正本は pm-session §5 に置き、ブリーフの型の「Story の完了の条件」から指す。

- 無人で走るもの（スケジュール実行など）を作る・変える作業は、Run now で通した後に、本番の時刻の1回を無人で通してから完了にする。
- 止まったら、確認の文と、止めたコマンドやツールを共有ノートに書く。直したら、次の本番の時刻の1回から数え直す。
- 待つ間、ボードの行は `done` にせず、`detail` に次の本番の時刻を書く。

人間が R2 として選んだ（派生先の Epic 1 の振り返り、2026-11-27）。決め手は M1 と W1。

## Consequences

### Positive

- 無人の実行が止まる形を、完了の前に見つけられる。
- 止まった記録が、次に直すときの手がかりになる。

### Negative

- 完了がスケジュールの間隔だけ延びる。
- 1回通っても、後の晩に別の形で止まることは塞がない（例: 権限モードの仕様が変わる）。
- 根拠は1件（Epic 1 の v1 と S7）だけである。

## Alternatives considered

- **無人の実行を、人間が答えられる時刻にだけ走らせる** — 夜のうちにコンテンツを用意するという、無人で走らせる理由がなくなる。
